# Pueblo settlement

The 27 source GLBs are in `C:/Users/green/Downloads/puebloBonito/output`; the originals stay there. `Tools/Pueblo/export_pueblo.py` imported the first 13 at about 7,000–10,000 triangles each. `Tools/Pueblo/export_new_pueblo.py` imports the 14 additional GLBs defined in `Tools/Pueblo/new_assets.json`, grounds and scales them, removes detached vertices if present, and decimates them more gently to 10,000–18,000 triangles. Its audit found no loose vertices in these 14 sources. Both pipelines export FBX and runtime base-color textures under `Models/`. The gate aperture is widened offline from about 0.8 m to 2.4 m; `Tools/Pueblo/audit_exported_gate.py` checks that the exported mesh remains open at standing height.

The wicker basket comes from the existing `C:/Users/green/Downloads/Props/wicker_basket_01_4k.blend.zip`. `Tools/Pueblo/prepare_basket.py` expands its Blender file into `Tools/Pueblo/work` and downsizes its diffuse texture; `export_basket.py` produces the FBX. The basket is physical and grabbable, but does not pretend to have a ceramic fracture. The source ZIP has no license text in its inspected members; confirm its rights before redistribution.

Use **Zandea > POI > Pueblo > Build Settlement** in Unity after import finishes. The idempotent builder creates static, concave-collider prefabs for the houses, ramadas, towers, walls and gate; four new ceramic containers are physical and grabbable, and the feeding trough is a ground prop. It creates `PuebloSettlement.asset` and `PuebloProps.asset`, a review scene at `Assets/Scenes/Zandea/PuebloSettlementReview.unity`, and a second stable POI in Main at least 800 m from the original outpost. Main's `Generated Layout Preview` shows the structures and props in edit mode; runtime disables that preview and streams the physical instances. Re-running preserves edited site coordinates.

The settlement uses the existing `BanditOutpost`, `OutpostLayout`, `OutpostTerrain`, and `OutpostPropPopulation` implementation. Its definition places five Pueblo buildings, including the new domed temple as main building, and six ramadas, with the new open ramada weighted three times. The other six new buildings are selectable variants; the tall watchtower replaces the round lookout. Wall runs mix all three Pueblo modules and reverse selected pieces. Its prop definition mixes the four new jars with the existing pot; a new feeding trough occupies a storage socket. Existing baskets, chest, barrel, crate, sacks, stool, table, rack and statue remain. The same terrain stamp, reservations, tile streaming, prop identities, and floating-origin handling apply. Six hostile bandits use the existing encounter and combat behavior. The standalone `stairCase` remains available but unplaced until roof access can be validated.

The review scene supports an editor visual pass without entering VR. After building, open it and run **Zandea > POI > Pueblo > Validate Review Scene**. `PuebloPlayValidation.RunBatch` also runs the 100-seed layout check and review-scene Play validation headlessly; the report is saved at `Tools/Pueblo/work/play-validation.txt`. The validator checks six hostile bandits, navigation, all three wall forms, new buildings and tower, six shades including the new ramada, new pots and trough, prop counts, gate-to-courtyard route, and terrain/collider coverage. **Zandea > POI > Pueblo > Validate Main Streaming** previously passed Main loading, navigation, stamped terrain/collider, props, and death recording, but its teleport-away unload step did not pass: the treadmill center tile stayed unchanged. Main travel/unload/reload and Quest headset collision feel and performance remain unverified.

## Albedo and normal-map editing

Run `python Tools/Pueblo/extract_albedo.py` to extract every source material's untouched 2048-pixel albedo into `Tools/Pueblo/work/albedo_exports/`. `manifest.json` maps each export to its GLB, material, and base-color factor. Run `blender -b -t 4 --python Tools/Pueblo/render_references.py` for reference images in `Tools/Pueblo/work/reference_renders/`. Pair an exported albedo with its reference render when editing textures. To use an enhanced image in Unity, replace `Assets/Zandea/Pueblo/Models/<key>_base.png` and optionally add `<key>_normal.png`; then run **Zandea > POI > Pueblo > Build Settlement**. The builder imports the optional normal as a normal map and connects it to the URP material. Keep the UV layout and image aspect ratio. These generated work outputs are ignored by Git and can be regenerated; the source GLBs are untouched.

The source meshes are deliberately rough. An offline source-versus-export render of `house_single` showed the large roof opening in the original GLB. Export uses decimation and grounding, not a mesh-cleaner pass that fills holes; the Unity materials are double-sided so thin surfaces are visible from either side. Inspect the other source models individually before interpreting any remaining open faces as an import defect.
