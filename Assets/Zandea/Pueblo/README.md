# Pueblo settlement

The building sources are the 13 GLBs in `C:/Users/green/Downloads/puebloBonito/output`. The originals stay there. `Tools/Pueblo/export_pueblo.py` grounds and scales each model, reduces its 40,000-triangle mesh to about 7,000–10,000 triangles, and exports a Unity FBX and 1024-pixel texture under `Models/`. The gate aperture is widened offline from about 0.8 m to 2.4 m; `Tools/Pueblo/audit_exported_gate.py` checks that the exported mesh remains open at standing height. This is a mesh-level check, not a Unity NavMesh pass.

The wicker basket comes from the existing `C:/Users/green/Downloads/Props/wicker_basket_01_4k.blend.zip`. `Tools/Pueblo/prepare_basket.py` expands its Blender file into `Tools/Pueblo/work` and downsizes its diffuse texture; `export_basket.py` produces the FBX. The basket is physical and grabbable, but does not pretend to have a ceramic fracture. The source ZIP has no license text in its inspected members; confirm its rights before redistribution.

Use **Zandea > POI > Pueblo > Build Settlement** in Unity after import finishes. The idempotent builder creates static, concave-collider prefabs for the houses, ramadas, round lookout, three wall forms, and gate, plus a grabbable basket prefab. It creates `PuebloSettlement.asset` and `PuebloProps.asset`, a review scene at `Assets/Scenes/Zandea/PuebloSettlementReview.unity`, and a second stable POI in Main at least 800 m from the original outpost. Main's `Generated Layout Preview` shows the structures in edit mode; runtime disables that preview and streams a fresh structure instance. Re-running the command preserves edited definitions and site coordinates, and only refreshes the review preview when prefab measurements changed.

The new settlement uses the existing `BanditOutpost`, `OutpostLayout`, `OutpostTerrain`, and `OutpostPropPopulation` implementation. Its definition places five Pueblo buildings and six ramadas, cycling through each selected variant before repeating, with mixed wall modules and a round lookout. Its own prop definition uses the existing pots, chest, barrel, crate, sacks, stool, table, rack and statue, adding baskets to canopy and storage areas. The same terrain stamp, reservations, tile streaming, prop identities, and floating-origin handling apply. Six hostile bandits use the existing encounter and combat behavior. No invented civilization NPCs or dialogue are added. The imported standalone `stairCase` is catalogued as a prefab but is not placed until roof access can be validated.

The review scene supports an editor visual pass without entering VR. After building, open it and run **Zandea > POI > Pueblo > Validate Review Scene**. Its Play Mode report at `Temp/ZandeaPueblo.play-validation.txt` passed six hostile bandits on navigation, prop population including pots and baskets, the gate-to-courtyard NavMesh route, and terrain/collider coverage. The component Inspector's **Validate 100 seeds** checks layout variation. **Zandea > POI > Pueblo > Validate Main Streaming** additionally passed Main loading, navigation, stamped terrain/collider, props, and death recording, but its teleport-away unload step did not pass: the treadmill center tile stayed unchanged. Main travel/unload/reload and Quest headset collision feel and performance remain unverified.

The source meshes are deliberately rough. An offline source-versus-export render of `house_single` showed the large roof opening in the original GLB. Export uses decimation and grounding, not a mesh-cleaner pass that fills holes; the Unity materials are double-sided so thin surfaces are visible from either side. Inspect the other source models individually before interpreting any remaining open faces as an import defect.
