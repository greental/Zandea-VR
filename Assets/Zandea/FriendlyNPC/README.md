# Friendly merchant integration

`DaranMerchantBuilder` is the authoring entry point. In Unity, choose **Zandea > Friendly NPC > Build Daran test scene**. It creates a Daran prefab, a reusable counter prefab, a personal purse, a payout pouch, dialogue and vendor assets, and `DaranMerchantTest.unity` under `Assets/Scenes/FriendlyNPC/`. The voice integration also saves `Assets/Scenes/FriendlyNPC/DaranMerchantVoiceTest.unity`, copied from the user's adjusted counter layout; open that scene to try the recorded dialogue without rebuilding the stall. Stock includes an existing physical sword and bo staff, plus an existing bandage prefab. The build checks D: free space first and stops below 20 GiB.

The merchant uses `CombinedStarvingBandit`'s CC_Base skeleton, `BanditRigMotion`, health and facial rig. Its Animator has no Avatar and is disabled by the existing rig driver. `StarvingBandit.hostileToPlayer` is false for Daran and stays true for existing bandits. Damage makes Daran hostile and ends dialogue. `MerchantHandshakePose` runs after `BanditRigMotion`: it folds Daran's arms at rest, adds restrained gestures, and reaches only while an offer is ready. `NPCFacialExpressionController` remains the sole owner of the expression blendshapes and jaw. Dialogue adds a bounded speech opening to that controller's existing jaw result.

Daran clears the inherited bandit `guardAuthoringMode` flag so `BanditRigMotion` restores his base pose each frame. His head offset is applied from a stored neutral rotation rather than multiplied onto the previous frame. Idle now blends a folded-arm pose over the inherited staff grip, with restrained upper-chest breathing and an occasional small glance and brief wave when the player approaches. The trade line presents the counter, and a valid offer extends the hand. The downloaded Lowpoly Dummy clips cannot be directly applied to this CC_Base rig because it has no Humanoid Avatar and `BanditRigMotion` disables its Animator. Reach and body language still need in-headset visual approval.

## Author dialogue and voices

### Daran's recorded pack

The project owner's 18 ElevenLabs recordings from `C:\Users\green\Downloads\Audio\DaranMerchant` are imported as real MP3 files in `Assets/Audio/Dialogue/Daran/`; the double `.wav.mp3` source suffix is normalized without transcoding. The source downloads remain untouched. `DaranVoiceBank.asset` maps semantic events to takes: `greeting_001` (two), `greeting_002` (two), `trade_offer_001` (one), `sell_ack_001` (one), `insufficient_funds_001` (two), `transaction_ready_001` (two), `trade_complete` (two), `farewell_001` (two), and three market-call groups containing four takes. Each take carries its own subtitle and 30 Hz baked mouth envelope. The voice bank avoids immediately repeating a take within a group. The two greeting groups alternate between conversations; only one greeting line plays per conversation.

`FriendlyNpcInteraction` remains the dialogue runner and requests lines by node/event ID. The counter requests a sell acknowledgment once when the first player-owned item is offered, and queues the handshake line when an offer becomes valid. Trade completion is spoken only after `TryCommit` succeeds. Ambient calls occur only while idle, at configurable 45–120 second intervals; conversation interrupts them. The 3D mouth AudioSource reaches 10 m for dialogue and 16 m for market calls. It never plays two clips simultaneously. Recorded lines are favored; dialogue nodes without a matching recording still show their authored subtitle without fabricated audio. The supplied pack has no recordings for the caravan/work line, settlement line, merchant-short-of-money line, rejected-item line, or canceled-trade line.

To add another NPC, create a `NpcVoiceBank` asset with event IDs matching its dialogue nodes and any additional contextual events. Add one or more `NpcVoiceTake`s per event; each take can override subtitle wording. Assign the bank to `FriendlyNpcInteraction` and populate `ambientEventIds` for optional idle calls. Select the bank and run **Zandea > Friendly NPC > Bake selected voice bank envelopes** before shipping. **Zandea > Friendly NPC > Import Daran voice pack** is a repeatable importer for the supplied local recordings; it preserves existing imported bytes and refuses a silent overwrite. The original ElevenLabs voice ID was not supplied, so the profile records the provider but does not invent a voice ID or require a runtime API key. Confirm the project's commercial voice rights before release.

Each `DialogueDefinition` contains stable node IDs, NPC ID, text, emotion, response links, actions, optional clips and baked mouth envelopes. `VoiceProfile` chooses the provider and voice. Nodes can override the default profile. Use `DialogueAction.QuestHook` for a future contract handler. To gate a node or response, assign a condition ID and a component implementing `IDialogueConditionSource`; a missing resolver rejects gated content.

To add an NPC, create a voice profile and dialogue asset from **Assets > Create > Zandea > Friendly NPC**. Attach `FriendlyNpcInteraction` to a compatible existing humanoid, assign the dialogue, facial controller, head AudioSource, conversation contact and palm choices, then assign any vendor counter. Avoid adding another facial controller.

Open **Zandea > Friendly NPC > Generate dialogue voice**. Select the dialogue and choose one line or the whole NPC. Generated files are placed at `Assets/Audio/Dialogue/<npc ID>/<node ID>_<hash>.wav` for Kokoro or `.mp3` for ElevenLabs. The hash includes text, provider, voice and speech rate. Existing files remain on disk when a line changes; the asset points to the new file after successful generation. An existing clip can also be dragged onto a node manually. Clip import bakes a 30 Hz amplitude envelope for the jaw, then sets compressed playback with audio data preloaded to avoid a first-line hitch. Runtime never calls a TTS provider.

Kokoro needs `kokoro` in a local Python environment plus its model download. Set the window's Python executable to that environment. The exporter is `Tools/Voice/kokoro_generate.py`. The default `am_michael` voice is listed in the upstream voice catalog; listen to a sample before final voice approval. The [Kokoro model card](https://huggingface.co/hexgrad/Kokoro-82M) states Apache 2.0 for its weights. Check the selected voice and dependencies before distribution, and retain any required notices. No model weights are bundled here.

ElevenLabs uses `ELEVENLABS_API_KEY` from the developer's environment. The key is never put in Unity assets or builds. Set `providerId` to `elevenlabs` and `providerVoiceId` to the chosen voice ID. Confirm the account's current commercial terms and voice rights before using generated clips in a release.

## Physical interaction

From 6–16 m Daran calls out to the market; at 3–6 m he plays one of two invitations. Within 3 m, wave a free controller hand with its palm facing Daran to start conversation. The player-side detector recognizes two deliberate sideways reversals and chooses the friendly NPC most directly under the headset gaze; approaching alone never opens dialogue. The old chest-grab target is disabled while idle. The conversation stays open within 9 m so the player can move around the stall. Raise the free left controller in front of the chest to reveal responses on a small physical notebook. Its position follows the tracked left interactor instead of the offset glove visual. The right stick cycles responses and A confirms; the right hand never carries the notebook. Lowering the left hand hides it. Choosing “I'll look around” dismisses the responses and keeps the trade open without repeating Daran's browse line. Dialogue reserves the left hand's grab/combat action while visible but leaves all locomotion and turn providers enabled. Quest 2 wave sensitivity, reach and text size still require headset tuning.

Merchant stock carries `TradeItem` with an existing `NpcItemDefinition`, instance ID and legal owner ID. Only release into the Buy or Sell area registers an offer. Grabbing removes it. The counter verifies identity, owner, position and current quote again at handshake. Item price labels show a red minus for purchases and a green plus for sales. `NetCats = sale proceeds − purchase costs`.

The red Buy and green Sell pads have open holding boxes extending 0.6 m above them. A valid item released by an XR grab is detected in the matching box and frozen with its pivot clamped inside the volume, so long pieces such as the bo staff cannot roll off. Stock merely sitting on a shelf is not automatically offered. Physical capture works before conversation starts; a price only appears during an active trade. Grabbing restores its previous Rigidbody settings and removes its quote. A cancelled offer keeps its goods suspended for safe retrieval, but no price or payment remains active; release the item again after reopening trade to offer it anew. The payment spot is separate and the purse is never merchandise. The purse and payout pouch use flat BoxColliders for stable counter placement; the raised net label shows the exact amount due and whether the purse has enough cats.

`BackpackUtilityAttachments` adds `CoinPurseAnchor` and a reserved `MapAnchor` outside the storage volume. The purse is one grabbable `CurrencyPouch` with one balance. Release it within 0.42 m of its exterior anchor, or inside the backpack volume, to snap it back without creating a copy. The payment spot accepts that personal purse but never prices it as merchandise. A completed debit waits until it is released, then remounts it. A merchant payout creates a separate pouch on the counter; hold the personal purse near that pouch and activate it, or release the payout pouch inside the usable backpack, to merge exactly its value. The payout is emptied and destroyed after merging.

The merchant's hand contact becomes selectable only when a valid offer exists. It displays a small "Grip to agree" cue and Grip calls `VendorCounter.TryCommit`; a forgiving controller-grip proximity check provides a fallback if XRI selection misses. The commit rechecks every offered object, final prices, purse position, and both balances. It creates a payout pouch before any mutation, changes goods and net currency once, and rolls back on an exception. Sold goods become merchant owned, leave the counter and appear on a stable upper stock shelf. The latest two sales remain visible and grabbable; older sales enter inactive overflow storage. Their IDs remain in the vendor's in-session stock list. Bought goods remain on the counter for pickup. A merchant-owned item carried more than 6 m away triggers a warning; at 9 m it is flagged stolen and raises `StockStolen`. Daran cancels the current trade, delivers an accusation and then switches the existing `StarvingBandit.hostileToPlayer` flag on. That hostility survives POI reload within the play session. `VendorCounter.becomeHostileOnTheft` can be disabled for a more forgiving merchant. There is no global faction reputation system in this project, so only the victim vendor reacts for now.

The supplied 18-clip pack has no warning or accusation recordings. Both lines are authored as `stock_warning_001` and `stock_stolen_001` nodes with a separate Kokoro `am_michael` voice profile. Their subtitles work now. To create their spoken clips, install Kokoro in a local Python environment, choose **Zandea > Friendly NPC > Generate dialogue voice**, select `DaranDialogue`, set that Python executable, and generate each of those two nodes. The generated clips and baked mouth envelopes are stored on the nodes; `FriendlyNpcInteraction` uses them for both ambient warnings and interruptions. An optional manually produced WAV named `stock_warning_001.wav` or `stock_stolen_001.wav` in `Assets/Audio/Dialogue/Daran/` is also recognized by **Import Daran voice pack**. Preview the new voice against the 18 recorded takes before release. The [Kokoro model card](https://huggingface.co/hexgrad/Kokoro-82M) lists Apache 2.0 for the model; its [voice catalog](https://huggingface.co/hexgrad/Kokoro-82M/blob/main/VOICES.md) lists `am_michael`. Check the voice and dependency terms for release. In this environment, Kokoro was absent and installation failed with a TLS handshake error from PyPI, so no theft audio is claimed to have been generated.

Individual item prices use larger plus/minus labels. A small paper ledger behind the trade areas lists up to six offered items and the net cats. It uses the [Caveat handwriting font](https://github.com/googlefonts/caveat), bundled with its [OFL license](Fonts/OFL.txt); `Zandea > Friendly NPC > Generate ledger font` rebuilds its TMP asset. The font glyphs are warmed when the counter loads, before the first offer is evaluated.
