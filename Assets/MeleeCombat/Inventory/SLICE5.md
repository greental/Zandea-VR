# Slice 5: physical NPC loot

The configured `StarvingBandit_BoStaff_Unified` prefab is already used by `BoStaffUnifiedVRArena.unity`. It now has `NpcClothingLoot`, which creates a trigger handle for each equipped garment after the cosmetics controller has fitted its visual. Handles are selectable only while `ScavengerHealth` is unconscious or dead. The handle has a kinematic Rigidbody and never pulls a ragdoll joint. Pull distance is measured in the moving garment handle frame. Releasing early or waking cancels the selection. A completed pull drops the existing `NpcItemInstance`, removes the worn appearance, and hands the physical garment to the same XR direct interactor. `LootManualHold` ends that manual handoff when grip is released. The existing martial hand code therefore sees a held item and does not punch with that hand.

`ClothingLootFactory` clones the garment's render meshes, bakes skinned meshes in the standing pose at spawn, transforms vertices into the garment frame, and flattens along the selected axis. It keeps UVs and all material slots, gives coincident surfaces minimum separation, recalculates bounds and normals, and uses one BoxCollider and Rigidbody. Imported shared meshes are never edited. Runtime mesh copies belong to `ClothingLootMeshes` and are destroyed with the physical loot object.

The **Kenshi VR > Loot > Bake Starving Bandit Clothing Prefabs** menu saves generated meshes and grabbable prefabs under `GeneratedLoot`, then assigns the prefab to the item definitions. The editor attempts this once after a successful script import if the prefabs are missing. Rigid garments use the cached prefabs; skinned garments continue to bake their fitted pose per NPC at spawn. If a cached prefab has not been built yet, runtime capture still works. `flattenAxis=None` preserves rigid equipment, and `flattenFactor`, `minimumThickness`, `lootEuler`, and `gripOffset` are Inspector settings on each `NpcItemDefinition`.

The shirt and pants currently refer to the project's existing scarf wrap and ragged skirt meshes. Their pocket contents were generated by Slice 4 and never rerolled. `PocketLootSpill` groups equal items into a single small grabbable object while retaining every logical item instance. Cats therefore spill as one pouch-like bundle. `NpcWorldItem.WorldObjectDestroyed` is an extension hook for future scene or terrain persistence; no disk save system exists yet.

Validation performed: Unity compiled Assembly-CSharp and Assembly-CSharp-Editor, the editor baked both prefabs, and the project's C# compiler response file passed with only the existing `ThermalPathHeatView.renderer` warning. Asset/prefab reference and whitespace checks are part of delivery. The headset interaction scenario, ragdoll orientations, terrain cases, and full Unity Play Mode sequence still require in-editor or headset validation and must not be considered tested by compilation alone.
